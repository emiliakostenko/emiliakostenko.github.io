Narrative

The artifact that I selected is my inventory tracking mobile app from CS360. The original version allowed users to perform CRUD operations for inventory items. Users were able to manage and keep track of inventory with screens for logging in, adding items, displaying current items, and managing item amounts. This app was created in October 2025.

This artifact will showcase skills that will make me more marketable. These include building an application that supports a diverse audience and is technically sound, showcasing innovative techniques. Techniques such as employing a binary search tree for efficient information retrieval and building an intuitive app through Android Studio that utilizes an SQLite database showcase technical skills. Additionally, this will showcase my ability to apply secure coding practices to reduce security vulnerabilities through proper error handling, input validation, authentication, and authorization. To improve my artifact, I added four new features, which include adding a search functionality utilizing a binary search tree algorithm, a feature to manage inventory items by a custom amount, adding folders to store inventory items within, and creating a description page for individual inventory items.

Reflection

As I started to implement the new tables for the features I had planned, I realized that I did not need one of the tables I had planned to add. The two tables I had planned to add were:

InventoryHistory (ItemId, PreviousCount, NewCount, DateModified)
LowStock (Columns: ItemId, Threshold)

Instead of adding a new table to track the low stock threshold, I decided to add the columns description and threshold to the existing InventoryTable. These two columns help support the new item description page and allow users to set a custom low inventory threshold for SMS notifications. Additionally, I updated the InventoryItem object to include the threshold and description attributes. This required me to sift through any uses of the object to ensure I updated the implementation everywhere these new attributes were needed. One thing I had not anticipated was the need for an additional table to support the folder page. As I developed this feature in the first enhancement, I realized it would be beneficial to have a separate table to support it. I also had trouble implementing a graph to visualize the data saved in the InventoryHistory table. After researching different approaches, I tried using one library, but after a lot of trial and error, I discovered it was outdated. Currently, there is no implementation to view inventory history insights in the app. Once I find a compatible charting library, the table and methods are already available for use.
